# 拷问环节(落盘时出题,用户回复后展开)

报告只能打写在纸上的东西。本文件规定怎样向用户追问**只有本人能回答**的问题——没写出的前提、默认的取舍、没想过的分支。

**拷问是取证,不是求共识。** 用户同意蓝军的判断,不算证据。

## 一、出题(报告落盘时,写入报告「七、待你回答的问题」)

**不出题的两种情形**:
- 范围显而易见的快查(如"审这句话有没有编造")——不设第七节。
- 筛完无题可出——报告末尾写一句"无需你补充的问题:<原因>",不设第七节。

**题只从本次报告的条目里取**:

| 来源 | 类型 | 问什么 |
|---|---|---|
| 命门假设 / 致命问题 | 事实型或决策型 | 成立与否取决于只有用户掌握的信息 |
| 🟡存疑 | 事实型 | 联网查无来源,但用户可能有内部数据或已做过验证 |
| D 盲区 | 是否考虑过型 | 这个替代方案/反例,用户此前是否考虑过 |
| 隐含的决策分支 | 决策型 | 材料做了选择,却没写为何不选另一条路 |

**三条筛选**:
- **能查的不问**:联网或读文件能回答的不列入清单,也不要求此刻补查,条目保持原标注。标"未深查"的条目,只有成立与否取决于用户内部信息时才出题。
- **材料已写明的不问**。
- **回答不会改变任何判定或建议的不问**。

**至多 8 题**。按决策依赖排序,上游在前;同层命门优先。超出 8 题按此顺序截取。

**每题写六项**(表格见 `report-template.md` 第七节):
1. 题号 `Qn`
2. 问题:一句话
3. 类型:决策型 / 事实型 / 是否考虑过型
4. 关联条目:报告 #几
5. 你的回答将怎样改变判定
6. 蓝军的判断——按类型写:
   - **决策型**:推荐答案 + 理由。
   - **事实型**:不猜答案,写判定门槛(回答达到什么程度该条才成立)。
   - **是否考虑过型**:写"你答后再说"。答前不亮蓝军看法。

清单末尾写一句:`回复题号或直接作答,我逐题追问;不回复则到此为止。`

出完题即结束本轮:**不追加提问,不等回复**。

## 二、展开(用户回复之后)

**先判断这条回复怎么处理**:
- 作答的不是用户本人(本 skill 由其他代理或脚本调用)→ 不展开。skill 自己升级到 Workflow 流水线不属此类,用户在场,照常展开。
- 回复与报告无关(如提出新请求)→ 不展开,报告保持原样,去处理新请求。
- 用户不按清单、直接反驳或补充报告里的某条判定 → 视为对该条目的作答,按逐题规则 4、5 处理并落盘;没有对应题号的记为 `补 1`、`补 2`。
- 用户在新会话里作答 → 先读报告全文和已有的拷问纪要文件,再按本节处理。

**逐题规则**:

1. **一条消息只提一个问题**。用户一次答了多题的,逐题判定、各自落盘,随后只追问其中最上游且仍不清的一题。用户只点了部分题号的,只处理这些题。判定完后提出清单中的下一题,并告知"还剩 N 题,随时说停"。
2. **每个回答当场判定**:站得住 / 存疑 / 被打穿。用户的回答对应的是清单里另一题时,当场处理并判定那一题,再回到原来的题;这次回答不计入原题的追问层数。
3. **含糊、回避或反问 → 同一题追问**,记 `Qn.1`、`Qn.2`,至多两层。两层仍不清 → 记 🟡,配一个最便宜的验证实验,转下一题。反问不算回答:决策型复述推荐答案并请表态,事实型复述判定门槛,是否考虑过型说明"你答完我再亮",各计一层。
4. **口头陈述不能把条目升 🟢**(铁律 6)。回答里可查的事实,主会话联网核实后据实判定,原判错了就改,并列出搜索词或 URL;查不了的内部事实标"用户自述,未核查",条目判定保持 🟡。
5. **已过复核闸门的 🔴 不因无证据的口头反驳下调**。下调须有可查证的证据;否则记"用户反驳,未核查",判定不变。
6. **新产生的 🔴 照常过【复核闸门】**。除此之外不派子代理。
7. **是否考虑过型的回答按三档记录**,只有第一档算"考虑过并否决":
   - 有事前痕迹:能指到早于本报告的文档、纪要、数据。
   - 当场给出理由,无事前痕迹。
   - 未给出理由,或承认没想过。

   用户给出的否决理由不论哪一档,都照常攻击。判定之后再亮蓝军对该替代方案的看法。
8. **每处理完一题立即落盘两处**(见第三节),不等拷问结束。

**停止**:清单的题全部处理完,或用户说停。停止时按第四节写入思维盲区观察。

## 三、落盘

**主报告**(可外发)追加「八、拷问后修订」,每题一行:题号、关联条目、条目判定变化(`原判 → 新判` 或"不变")、修订后的建议。第一至六节原文不改写;"最该先补的 3 件事"有变,在第八节末尾注明。

主报告会被转发,所以第八节**不写用户说了什么**:
- 不写原话,也不转述。"条目判定变化"只写判定结果和依据来源(如核实所用的 URL)。
- "用户自述,未核查""用户反驳,未核查"、用户口头论据被证伪的经过,只写进私人纪要。
- 条目判定没变的题,该列只写"不变"。
- 不写思维盲区观察。

**私人纪要文件**(不外发)与报告同目录,文件名 `<报告文件名去掉扩展名>-拷问纪要.md`,首次落盘时创建:

```markdown
# 拷问纪要:<报告标题>

> 私人文件,含原话,不外发。对应报告:<报告文件名>

## 拷问纪要

| # | 问题 | 用户回答(逐字摘录) | 回答判定 | 蓝军看法 |
|---|---|---|---|---|
| Q1 | <问题> | "<原话,不归纳不演绎>" | <站得住/存疑/被打穿;是否考虑过型另记三档之一;自述标"用户自述,未核查"> | <判断 + 理由;核实过的列搜索词或 URL> |

## 思维盲区观察

| 推理模式(观察,待验证) | 出处(≥2 处,相互独立) | 对策 |
|---|---|---|
| <具体到本材料的一句话> | <#3、Q4> | <可执行的做法> |
```

## 四、思维盲区观察的收录规则

一条推理模式**同时满足四项**才收录:

1. **重复 ≥2 次**,每一处都列出处(条目 # 或题号)。
2. **各处相互独立**:须来自不同条目或不同题。同一题及其追问合计一处;用户在回答里为某条目辩护时复述该条目的推理,与该条目合计一处。
3. **具体到本材料**:把这句话套到任意一份方案上同样成立的,不收录。
4. **作者归属**:想法模式下用户提出的想法计入;文档模式下,除非用户说明材料出自本人,否则只计用户的回答,不计材料。

每条写模式、出处、对策。只评推理模式,不评人(铁律 7):模式指怎样从前提走到结论;答题的态度、配合程度、拿不拿得出材料,不是推理模式,不收录。没有符合条件的模式时,整节只写"未观察到重复模式"。

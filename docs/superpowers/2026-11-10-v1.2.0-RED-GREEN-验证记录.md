## 二、GREEN(v1.2.0,自挑战修订后的设计)

### 测试方式与它的局限

　　被测对象是修订后的设计:报告落盘时出题,用户回复后才展开。场景与核对项见实施计划"自挑战后修订"一节。

　　测试子代理读取仓库内的新版 skill,操作夹具报告的副本。模拟的用户回复逐条存为编号文件,子代理每发出一条消息后才读取下一个文件,并把发给用户的消息逐字记入对话记录。这种做法把多轮对话压进一次子代理运行,有三点局限:

- 它不是真实的逐轮交互。除场景 C 外,规则是在短上下文里被执行的。
- 回复文件的隔离靠子代理自觉。场景 A、A2、A3 的子代理开头都做过一次目录匹配,看到了回复文件名(未读内容);场景 C 第一条回复的读取与上一条消息的写入在同一批操作里。出题均在读取回复之前完成。
- 运行环境拒绝子代理新建报告类 `.md` 文件。私人纪要文件只在场景 C 建成(该子代理先写暂存文件再改名),其余场景把纪要全文放进了对话记录。主会话的写入路径不受此限制,但未经测试。

　　各场景多次因用量上限中断,均恢复原子代理续跑,没有重开。

### 未处理的发现

- 场景 A 中各题的"验证实验"多为落笔动作(把定位写成一页纸),只有一题是真正的实验。未改规则。
- 场景 A 中蓝军称夹具报告的 🔴"已过复核闸门",而夹具是旧版样例,没有闸门记录。这是夹具造成的,未改规则。
- 场景 A、A2 中,蓝军在写入结果返回之前就告知"已写入私人纪要",随后更正。成因是测试环境拒绝写入;未改规则。
- 第七节个别题目一题含两问。未改规则。
- 旧计划中的两种情形没有测试覆盖:用户反问;用户以可查证的事实反驳原判。

### 上线后须确认的事项

- 主会话首次真实使用时,确认私人纪要文件能建成、逐题写入。
- 按 spec 第七节回看:前 5 次带第七节的真实报告之后,检查用户是否回复过清单、第二层追问是否有增量、是否有判定因拷问改变,并按既定的降级线处理。

　　一名没有本会话上下文的独立审查者复核了全部提交,结论为"修完再合并":无严重问题,8 条重要问题,13 条次要问题。8 条重要问题全部进入一轮修补;次要问题未处理,列于本节末尾。

### 修补与复跑(场景 A5)

　　场景 A5 用 4 条回复覆盖此前零覆盖的情形:带可查事实的直接反驳、反问、一次答三题、叫停。

| 验证记录的局限不全,证据将被清理 | 见下"补充的局限";对话记录已归档 | 不适用 |

### 补充的局限

- **正常路径几乎没有覆盖。** 脚本回复不随问题变化。场景 A 的 8 条回复里没有一条是正面、清楚地回答了所问的题;只有 A5 有三条正面回答。所有运行里"条目判定变化"都是"不变","原判 → 新判"从未出现。A5 中事实反驳导致的是更正报告表述,不是改判。
- **场景 B 的报告没有落盘。** 写入被运行环境拒绝,报告全文只在子代理的回复里,未留存;"报告无第七节"的依据是该回复。
- **出题一致性没有单独跑。** 取的是 A、A2、A3、A4、A5、C 六次运行的出题阶段,题数在 6 到 8 之间。
- **作者归属规则没有覆盖。** 所有展开都是想法模式,文档模式的场景 D 只出题。
- **未测的路径**:作答者不是用户本人;无题可出;走 Workflow 流水线或降级策略时第七节是否写入;新会话作答;事实型与"是否考虑过"型的反问。
- **长上下文的样本很小。** 场景 C 是一个实质回答加一次叫停;纪要文件两题以上的逐题追加没有验证过。
- **同一句回复两次判定不同。** "靠通讯录导入就能解决"在场景 A 判 🟡,在 A4 判 🔴 并过闸门。
- **没有真实的轮次边界。** "出完题即止、不等回复"与"展开时重读规则"在单次子代理运行里测不到。
- **自挑战的来源抽查不是主会话亲手做的。** 主会话没有 WebFetch 工具,由专门的抓取子代理代做。

### 归档的证据

　　场景 A、A4、A5、C 的对话记录归档在 `docs/superpowers/2026-11-10-v1.2.0-验证对话记录/`,内容是脚本回复与被测子代理的消息。其余测试产物随临时工作区清理。

### 未处理的次要问题(终审提出)

1. "不追加提问"与文档模式第 6 步"收尾可选:问用户是否推到飞书任务"字面冲突。
2. 规则 3、4 中的"记 🟡"没说记在哪;关联条目是 🔴 时可能被读成把 🔴 改 🟡。两次运行都处理对了。
3. 回答的三个判定词与想法模式的判定档同名,容易把"回答站得住"混同为"条目升 🟢"。
4. spec 的"第七节出题后不改"没有写进 skill 文件。
5. 报告模板写"回答会改变判定",少了"或建议"。
6. 材料不是用户写的情形,出题一侧没有规定是否还出"是否考虑过"型题。
7. 用户明说"跳过这题"没有规定,目前靠模型自行尊重。
8. 用户中途离开时,纪要里的思维盲区一节会一直留着占位。
9. 私人纪要与报告同目录,目录若在 git 仓库或同步盘里可能被一并带走。
10. 第三、四节的条目没有编号,关联条目的写法不统一;"同层命门优先"在文档模式没有定义。
11. `samples/` 的两份样例不含第七节,已不代表 v1.2.0 的输出。
12. 实施计划的作废说明只覆盖"下文",其上的 Global Constraints 与 Review Focus 仍是旧表述。
13. 自挑战报告的闸门记录没有写明抽查由抓取子代理代做(本记录已补)。

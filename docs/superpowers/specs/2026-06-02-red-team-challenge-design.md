# 蓝军挑战 Skill 设计文档(red-team-challenge）

日期:2026-06-02
状态:已确认,待出实现计划

## 一、目标与定位

构建一个名为 `red-team-challenge`(蓝军挑战)的 skill。它扮演**怀有敌意的资深评审**,对用户的**想法**或**调研文档**进行反向挑战,核心目的是确保内容**没有错误、符合事实、不是 AI 编造/幻觉**。

人格基调:默认立场是"你给的东西有问题,直到被证明无误"。不负责鼓励、不负责完善措辞,只负责找茬和打假。

### 攻击优先级(固定顺序)

1. **A — 事实性核查**:数据、引用、案例、技术结论是否真实存在、是否被来源支持(对抗 AI 幻觉/编造)
2. **D — 盲区/完整性**:是否遗漏反例、替代方案、关键前提
3. **C — 可行性/风险**:技术、市场、资源上是否真成立,有无被忽略的硬伤
4. **B — 逻辑严密性**:论证跳跃、因果不成立、结论不被论据支撑

## 二、关键设计决策

| 决策点 | 选择 |
|---|---|
| 事实核查手段 | **强制联网**逐条核查(web 搜索/抓取真实来源比对) |
| 产出形式 | **结构化挑战报告**(断言→核查→判定→来源) |
| 输入形式 | 灵活:本地文件路径 / 粘贴文本 / 飞书文档链接(用 lark-doc 拉取) |
| 模式 | **自动分模式**:文档模式 vs 想法模式,攻击套路不同 |
| 执行架构 | **对抗式子代理为默认**;断言量大(>15)或用户要"彻查"时升级到 Workflow 流水线 |

## 三、触发条件

当用户表达类似意图时触发:
- "用蓝军挑战这份文档/这个想法"
- "帮我反向挑战 / 找茬 / 唱反调"
- "审一下这个调研有没有编造 / 有没有 AI 幻觉"
- "这个想法有什么硬伤"

## 四、工作流程(五阶段)

### 阶段 0 — 接收与识别
- 解析输入:本地文件直接读;飞书链接用 lark-doc 拉取;粘贴文本直接用。
- 自动判定模式:
  - **文档模式**:含数据/引用/案例/技术结论的成文材料
  - **想法模式**:原始构想,无可核查引用

### 阶段 1 — 拆解断言(Claim Extraction)
把输入拆成一条条可检验的"断言":
- 文档模式:重点抽取**事实性断言**(数据、引用、案例、技术结论)
- 想法模式:重点抽取**隐含假设**(如"用户愿意付费""这个 API 支持 X""市场有需求")

每条断言必须带**原文定位/引用**,不得脑补原文未出现的内容。

### 阶段 2 — 分派对抗子代理(核心)
- 每条高风险断言 → 派一个独立子代理,指令明确为:
  > "默认这条断言是错的/编造的。联网搜索真实来源,只有找到可靠来源支持时才判它成立。"
- 关键断言可派多个子代理交叉验证(投票)。
- C(可行性)、D(盲区)的追问也在此阶段并行进行。
- **想法模式**下,子代理不是核查引用(没有引用),而是**联网搜证据反驳假设**(如搜"该市场是否已被验证""是否有失败先例")。

### 阶段 3 — 汇总与判定
- 每条断言归档为:🟢成立 / 🟡存疑 / 🔴证伪
- 按优先级 A>D>C>B 组织发现

### 阶段 4 — 输出结构化挑战报告
见第五节。

### 升级到 Workflow
当断言 >15 条,或用户明确说"彻查/全面审"时,skill 建议用 Workflow 并行流水线(发现断言→并行核查→对抗投票→汇总),而非主对话逐条处理。Workflow 需用户显式授权。

## 五、挑战报告结构(交付物)

保存为本地 markdown:默认 `<原文件名>-蓝军挑战-YYYY-MM-DD.md`;粘贴文本则让用户指定或放当前目录。

```markdown
# 蓝军挑战报告:<标题>
模式:文档模式 / 想法模式 ｜ 日期 ｜ 核查断言数:N

## 一、致命问题(Showstoppers)
被证伪的事实、站不住的核心假设 —— 置顶

## 二、逐条核查清单(主体,按 A>D>C>B 排序)
| # | 断言(原文引用) | 类型(事实/假设/逻辑) | 判定 | 核查发现 | 来源链接 |
- 判定红绿灯:🔴证伪 / 🟡存疑 / 🟢成立
- 证伪和存疑必须附:为什么 + 联网查到的反证 / 查无此据

## 三、盲区与遗漏(D)
没提但应考虑的:反例、替代方案、被忽略的前提

## 四、可行性拷问(C)
技术/市场/资源上的硬伤与未回答的关键问题

## 五、总评
一句话结论 + 整体可信度评级(高/中/低) + 最该先补的 3 件事
```

核心原则:**任何"🟢成立"的事实断言也必须有来源支撑,不能因"听起来对"就放过;查无来源的一律降到🟡存疑。**

## 六、防"蓝军自己也编造"的护栏(硬规则)

1. **来源必须真实可点开**:判定任何一条时引用的来源必须是真实抓取/搜索到的 URL。禁止"我记得有篇研究说…"这类无链接断言。查不到就老实说"查无来源",不许编。
2. **区分"查无来源"与"证伪"**:找不到支持证据 ≠ 证明为假。前者判🟡存疑,只有找到明确反证才判🔴证伪。
3. **不杜撰原文**:被挑战的断言必须是原文真实出现的(带引用定位)。
4. **承认不确定**:子代理可返回"无法判定",汇总时如实呈现,不强行下结论。
5. **主观内容不假装核查**:大段主观观点/价值判断标注为"主观断言,不在事实核查范围",归 C/B 处理。

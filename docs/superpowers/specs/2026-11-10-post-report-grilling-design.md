# 蓝军挑战 v1.2.0 设计文档:报告后拷问

日期:2026-11-10
状态:设计已口头确认,待审阅本文件;审阅通过后出实施计划
涉及版本:red-team-challenge v1.1.0 → v1.2.0

## 一、背景与目标

　　现版蓝军只能攻击写在纸面上的内容。留在提出者头脑里的部分它够不着,包括没有写出的前提、已经默认的取舍、尚未想过的分支。想法模式的"拆假设"由子代理代为推测,推测不中的假设就此漏掉。

　　本次升级借用 grill-me skill 的四点做法,补上这一缺口:

1. 逐个追问,一次只问一个问题,把头脑里的内容逼到纸面上。
2. 沿决策树提问,先问上游决策,再问依赖它的下游决策。
3. 每个问题附带提问方的推荐答案,蓝军不仅发问,还要亮出自己的判断。
4. 能查的不问,联网或读文件可以回答的,由蓝军自行查证。

　　升级后应达到三个目标:对方案的评价更全面;能区分"方案的盲区"与"提出者思维上的盲区";每条发现都落到可执行的建议上。

## 二、约束

　　以下约束来自 2026-06-20 自挑战复盘的结论,本次设计不得违反:

- 开火前不设阻塞步骤。复盘中 R7"阻塞式前置契约"即因此被否决。
- 默认不净增子代理。
- 不稀释 🔴 复核闸门与 8 条铁律。铁律 7"对事不对人"保持原文,本次所说的"评价提出者",对象是其推理、决策与思维模式,不是其本人或动机。
- 🟡(查无来源)与 🔴(找到反证)的区分保持不变。

## 三、关键设计决策

| 决策点 | 选择 | 否决的备选及理由 |
|---|---|---|
| 拷问的位置 | 报告落盘之后 | 开火前拷问:与 R7 结论冲突。独立拷问模式:多一套流程需维护和验证,待本方案运行稳定后再议 |
| 启动方式 | 报告后直接提出第一个问题,并预告问题数量;无值得问的问题则不问 | 先征询"要不要拷问":多一轮无信息量的往返。仅在用户明说时启动:多数情况下不会被用到 |
| 思维盲区的输出 | 仅写重复出现两次以上、且能指到具体条目的推理模式,每条配对策 | 不设该节:无法回应"思维盲区"目标。出现一次即可点评:单例归纳为习惯等同于编造 |
| 深度与停止 | 沿决策树追问至命门分支全部有判定;每分支最多追问两层;用户可随时叫停 | 固定清单不追问:实为问卷,盲区多在第二层追问才暴露。不设上限:成本不可控,与 R6 开放循环被否理由相同 |

## 四、设计

### 4.1 位置与豁免

　　在 SKILL.md"报告落盘"一节之后新增"拷问环节",文档模式与想法模式共用。现有阶段 0、两种模式的流程、复核闸门、8 条铁律、Workflow 升级与降级策略均不改动。

　　范围显而易见的快查(例如"审这句话有没有编造")免拷问,与现版"锁定靶子"的豁免条件一致。

### 4.2 问题来源

　　拷问的问题只从已落盘的报告中产生,共四类:

| 来源 | 提问内容 |
|---|---|
| 命门假设、致命问题 | 该条成立与否取决于只有用户掌握的信息 |
| 🟡 存疑条目 | 联网查无来源,但用户可能持有内部数据或已做过验证 |
| D 盲区条目 | 该替代方案或反例,用户是考虑过并已否决,还是未曾想到 |
| 隐含的决策分支 | 材料做了选择,却未说明为何不选另一条路 |

　　第三类是识别思维盲区的主要手段:考虑过并否决的,要求给出否决理由;未曾想到的,记为盲区。

　　筛选规则有两条:

- 能查的不问。联网或读文件可以回答的问题,由主会话自行查证,不向用户提问。
- 材料已写明的不问。

　　筛选后若无问题可问,用一句话说明不拷问的原因,流程结束。

### 4.3 问题排序与数量

　　问题按决策依赖关系排序,上游决策在前,依赖它的下游在后。上游的回答使下游问题失效时,跳过该下游问题。同一层级内,命门级问题优先。

　　提出第一个问题时,预告估计的问题总数,并说明可随时叫停。常态为 5 至 8 问;预计超过 8 问时,先告知用户再继续。

### 4.4 单个问题的格式

　　每次只提一个问题,固定包含三部分:

- 问题:一句话。
- 为什么问:关联报告第几条;用户的回答将如何改变该条的判定。
- 蓝军的推荐答案:蓝军自己的判断及理由。

### 4.5 回答的处理

　　每个回答当场给出判定,沿用想法模式的三档:站得住、存疑、被打穿。处理规则如下:

- 回答含糊或回避时,在同一分支上追问,每个分支最多追问两层。两层之后仍不清楚的,记为 🟡,并配一个最便宜的验证实验。
- 用户的口头陈述不能把条目升为 🟢。铁律 6 要求 🟢 必须有来源支撑,因此回答中可查证的事实由主会话联网核实;无法查证的内部事实标注"用户自述,未核查",该条判定保持 🟡。
- 拷问中新产生的 🔴 照常过复核闸门:有反证 URL 的走反向复核加来源抽查,纯逻辑的走纯逻辑分支。
- 拷问全程由主会话完成,不派子代理;唯一例外是新 🔴 过复核闸门时按现有规则派反向复核子代理。

### 4.6 停止条件

　　满足以下任一条件即停止:

- 命门级分支全部已有判定。
- 用户叫停。
- 用户未回答第一个问题而对话结束。此时报告保持原样,不追加任何内容。

### 4.7 产出

　　拷问停止后,在原报告文件末尾追加以下内容:

- 七、拷问纪要。表格列为:序号、问题、关联条目、蓝军推荐答案、用户回答、回答判定、条目判定变化、修订后的建议。"用户回答"一列忠实摘录原话,不归纳、不演绎。
- 八、思维盲区观察。每条包含:模式、出处、对策。只收录在材料与用户回答中重复出现两次以上的推理模式,"出处"必须列出具体条目编号或第几问。没有符合条件的模式时,写"未观察到重复模式"。
- 未拷问清单。用户叫停时尚未提出的问题,逐条列出。全部问完则省略此项。

　　用户在回答任何问题之前即明确叫停的,只追加未拷问清单,第七、八节省略。

　　对原有内容的修改遵守两条规则:

- 报告第一至第六节的原有条目不静默改写。判定发生变化的,在拷问纪要的"条目判定变化"一列记为"原判 → 新判(第 N 问)"。
- 第五节总评中"最该先补的 3 件事"如因拷问而变化,在该节原内容之后追加"拷问后修订"一行,不覆盖原内容。

　　文档模式的报告没有第六节(事前验尸仅用于想法模式),新增两节的编号仍固定为七、八。

## 六、验证计划

　　按 `superpowers:writing-skills` 的 RED→GREEN 纪律与本项目的自挑战惯例,分四步:

1. RED 基线。用现版 v1.1.0 跑一份样例材料,记录两点:报告落盘后是否向用户追问;能否区分"考虑过并否决"与"未曾想到"。
2. 自挑战。把本设计文档交给现版蓝军按想法模式挑战,依据结果删减或修订设计。修订如涉及第三节的决策,回到用户确认。
3. GREEN 复跑。修改完成后,用子代理加载新版 skill,并配以脚本化的用户回答,覆盖三种情形:含糊回答、回避、回答中夹带新的事实断言。逐项核对下表。
4. 撰写复盘,存入 `docs/superpowers/`,然后部署。

| 核对项 | 通过标准 |
|---|---|
| 一次一问 | 每条消息只含一个问题 |
| 问题格式 | 三部分齐全,含蓝军推荐答案 |
| 能查的不问 | 无可联网查证或材料已写明的问题 |
| 追问上限 | 同一分支追问不超过两层 |
| 不因自述升 🟢 | 无来源的用户陈述未使任何条目变为 🟢 |
| 新 🔴 过闸门 | 拷问中产生的 🔴 均有复核记录 |
| 思维盲区门槛 | 模式不足两次时,第八节写"未观察到重复模式" |
| 忠实摘录 | "用户回答"一列与脚本化回答原话一致 |
| 原条目不静默改写 | 第一至第六节原文未被覆盖 |
| 快查豁免 | 单句核查类请求不触发拷问 |

　　第 2、3 步需派多个子代理并联网检索,是本次升级的主要成本。

## 七、已知风险

| 风险 | 说明 | 当前处理 |
|---|---|---|
| 推荐答案带偏用户 | 用户先看到蓝军的推荐答案再作答,可能顺着说 | 沿用 grill-me 原做法予以保留;列为自挑战的重点攻击对象,视结果决定是否改为"用户答后再亮推荐答案" |
| 报告变长、不宜外发 | 拷问纪要含用户原话,报告转发他人时可能不合适 | 当前设计为追加在同一文件;若自挑战或试用中证实是问题,改为纪要单独成文件 |
| 快查场景被打扰 | 每次报告后都可能多出一个问题 | 4.1 的快查豁免;GREEN 核对项中单列验证 |
| 思维盲区一节经常为空 | 单次挑战样本小,多数模式凑不够两次 | 接受。空着优于硬写 |
| 主会话漏执行 | SKILL.md 条件分支增多,拷问环节位于流程末尾,可能被跳过 | GREEN 复跑中观察;如出现,将拷问环节写入两种模式流程的编号步骤 |

## 八、不做的事

- 不新增独立的拷问模式。
- 不在开火前提问。
- 不让子代理参与拷问。
- 不跨会话保存用户的思维模式记录。第八节只基于单次挑战的材料与回答。
- 不改动复核闸门、8 条铁律、判定档定义与攻击优先级。
